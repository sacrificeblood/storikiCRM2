# Minon Devils — сервер

Node.js/Express-сервер + Postgres с закрытым доступом, ролями и отдельными
рабочими пространствами баеров.

## Из чего состоит

```
server.js      — Express: REST-хранилище для доски, история/бэкапы, /api/health
db.js          — подключение к Postgres, создание таблиц при первом запуске
public/index.html — сама доска (фронтенд)
.env.example   — какие переменные окружения нужны
```

## Проверка базы

Откройте `https://ваш-сайт/api/health` — покажет, жива ли база.

## Запуск

```
npm install
npm start
```

Переменные окружения (`.env`, скопировать из `.env.example`):
```
DATABASE_URL=<строка подключения к Postgres>
NODE_ENV=production
PORT=3000
TELEGRAM_BOT_TOKEN=<токен бота>
TELEGRAM_CHAT_ID=<id чата>
ADMIN_EMAIL=<твой email для первого входа>
ADMIN_PASSWORD=<длинный уникальный пароль>
```

После первого деплоя откройте сайт и войдите через созданный админ-аккаунт.
Во вкладке «Участники» админ создаёт баеров, а баер — ассистентов. У баера и
его ассистентов одно рабочее пространство; ассистент может только просматривать
данные, баер редактирует рабочий контент, но в задачах меняет только статус.

## Задачи и Telegram

После первого запуска появятся две ежедневные задачи: внесение вчерашнего spend в 10:00 и отправка spend/revenue в чат в 20:00 (время Киева). Во вкладке «Задачи» есть отдельная кнопка для создания ежедневной задачи, настройка времени, ручное включение/выключение уведомлений и таймер до следующего сообщения. Выполнение подтверждается в отдельной колонке «Подтвердить выполнение». После срока бот напоминает каждые 5 минут, пока задача не подтверждена.

Напоминания выполняет сам сервер, поэтому Web Service на Railway/Render должен быть постоянно запущен и не переходить в sleep-режим.

## Деплой

GitHub → Railway (или Render) → New Web Service → указать `DATABASE_URL` в Environment → Deploy.
